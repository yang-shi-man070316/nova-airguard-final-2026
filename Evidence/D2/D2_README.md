# D2 持续风险与优先关注 模块说明

## 1 模块目标

当多个区域同时出现不同程度异常，系统自动计算风险优先级，选出**当前优先关注区域**，并给出可解释的判定理由。

## 2 数据来源与置信度

- crowdLevel **保留 source 标记**：报文可选字段 `crowdSource`、`crowdConfidence`，随区域状态留存与展示（缺失时按 simulated 处理）
- simulated / rule / review 来源：按本 README 声明的规则**直接使用**，置信度采用来源声明值 1.0
- model / template 等自动感知来源：置信度**低于 0.2 阈值（或缺失）**的结果不得直接驱动优先处置——该区域人流附加分不计入总分，并在界面标注「**需人工复核**」
- 本系统**不伪造模型置信度**：自动感知来源缺失 confidence 时按低于阈值保守处理，不补默认高置信值

> 说明：本项目人流等级为模拟数据（simulated），规则驱动生成，按来源声明置信度 1.0 直接参与优先级计算，无需人工复核。

## 3 优先级计算规则（可解释、可重复）

总分 = 环境基础分 + 人流附加分 + 持续异常加成

### 3.1 环境基础分

| 环境 status | 得分 |
|---|---|
| 重度污染 | 10 分 |
| 轻度污染 | 6 分 |
| 通风不足风险 | 4 分 |
| 正常 | 0 分 |

### 3.2 人流附加分 crowdLevel

| crowdLevel | 含义 | 附加分 |
|---|---|---|
| 2 | 拥挤 | +3 分 |
| 1 | 一般 | +1 分 |
| 0 | 空闲 | +0 分 |

> 注：crowdLevel=3（严重拥挤）在拥挤之上延展，+5 分。

### 3.3 持续异常加成

连续收到异常报文次数 ≥2，额外 +2 分。

> 异常定义：status != "正常"。连续异常计数随每条异常报文 +1，一旦恢复正常立即清零。

### 3.4 同分兜底排序规则

1. 优先对比【连续异常次数】，次数更大的区域优先级更高
2. 若连续异常次数相同，按环境等级权重：重度污染 > 轻度污染 > 通风不足风险
3. 全部区域总分 = 0：所有区域正常，无优先关注区域

## 4 程序逻辑说明

1. 每个区域独立维护状态：当前 status、crowdLevel、上报时间、**连续异常计数**（三区域数据隔离，互不干扰）
2. 每次收到 MQTT 新报文：
   - 新 status 为异常：该区域连续异常计数 +1
   - 新 status 恢复正常：连续异常计数清零
3. 遍历全部 3 个区域，逐个计算风险总分，选出最高分区域作为优先关注对象
4. 判定理由文本自动生成，描述风险来源：持续异常时长、人流等级、综合风险分数
5. crowdLevel 来源处理：simulated / rule / review 按声明规则直接使用；model / template 等自动感知来源低于 0.2 阈值或缺失 → 人流附加分不计入、标注「需人工复核」，不得直接驱动优先处置

## 5 可复现性说明

规则全部硬编码在前端 JS，**没有固定写死 zone-w 为优先区域**。输入不同的三组区域数据，优先关注区域会跟随数据变化，结果可重复、可解释。

## 6 D2 证据测试用例（3 组）

### Case1

- zone-n：正常
- zone-s：单次通风不足风险
- zone-w：连续多次重度污染，crowdLevel=2

✅ 输出：优先关注 zone-w
理由：环境异常持续更久，人流密度等级高，综合风险分值最高。

### Case2

- zone-n：正常
- zone-s：重度污染
- zone-w：轻度污染

✅ 输出：优先关注 zone-s
理由：环境污染等级更高，综合风险分值最高。

### Case3

- zone-n、zone-s、zone-w 全部区域状态正常

✅ 输出：所有区域状态正常，无优先关注区域

## 7 与其他模块联动

- D2 复用 D1 的 MQTT 数据流、status 计算函数，三端（总视图、3D 页面）共用同一套优先级逻辑
- 总视图 index.html 展示 D2 优先关注面板（优先区域、判定理由、三区域打分表格）
- three-min.html 3D 模型增加轻微闪烁动画标记优先区域，左侧面板同步显示判定理由
