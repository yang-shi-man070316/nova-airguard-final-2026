# D3 干预—验证—恢复 模块说明

## 1 模块目标

异常预警不只是告警，完整事件生命周期：发现异常 → 优先关注 → 用户干预 → 数据验证 → 恢复/未恢复 → 事件复盘记录。

采用显式状态机管理事件，严格限制状态转移，处理重复、乱序、迟到的 MQTT 消息。

## 2 事件状态定义

| 状态 | 含义 |
|---|---|
| OPEN | 待处理，已经发现异常，等待用户干预 |
| HANDLING | 处理中，用户已经执行干预动作，持续接收新数据做验证 |
| RECOVERED | 已恢复，验证数据满足恢复条件，事件归档 |

## 3 显式状态转移规则

| 当前状态 | 目标状态 | 触发条件 | 说明 |
| ---- | ---- | ---- | ---- |
| 无状态 | OPEN | 出现新异常 | 创建新事件 |
| OPEN | HANDLING | 用户点击干预按钮 | 必须人工干预动作 |
| HANDLING | RECOVERED | 后续新数据满足恢复条件 | 必须由新监测数据触发 |
| HANDLING | OPEN | 新数据显示异常恶化，干预无效 | 允许回退 |
| OPEN/HANDLING | 保持不变 | 仅点击按钮，无新数据 | 不能变更状态 |

补充说明（与实现一致）：

- HANDLING 期间收到「异常改善但仍未恢复正常」的数据：状态保持 HANDLING，数据存入验证列表，连续正常计数中断
- 同一区域同时只存在 1 个活跃事件，短时间异常合并到同一事件

### 禁止非法状态跳转

1. OPEN 不能直接跳 RECOVERED，必须经过 HANDLING 干预验证环节
2. 低置信度感知数据不能触发 HANDLING→RECOVERED，标记需人工复核
3. 已经 RECOVERED 的事件，迟到/重复消息不能把事件改回 HANDLING

## 4 事件字段定义

每个事件对象包含：

| 字段 | 说明 |
|---|---|
| event_id | 事件唯一标识（EVT-zone-时间戳） |
| zoneId | 所属区域 |
| startTime | 事件开始时间 |
| 异常描述 | 异常状态与人流情况描述 |
| 优先理由 | 创建时取自 D2 判定理由（若为当前优先关注区域） |
| userAction | 用户干预动作（开启新风 / 喷雾降尘 / 限流疏导） |
| verifyDataList | HANDLING 期间收集的验证数据 |
| currentState | OPEN / HANDLING / RECOVERED |
| recoverTime | 恢复时间 |
| finalResult | 恢复结论文本 |

## 5 恢复判定规则

1. 仅环境异常：连续 2 次上报 status=正常，判定恢复
2. 环境异常+人流拥挤：环境 status 连续 2 次正常 **并且** crowdLevel ≤1，判定恢复

> 低置信度（confidence < 0.2）的感知数据不满足恢复触发条件，事件保持 HANDLING 并标记「需人工复核」。

## 6 消息健壮性处理

1. 重复消息：优先使用 payload.msgId（message id）作为去重依据；无 msgId 时使用 zoneId + time + 关键荷载（pm25/co2/crowdLevel）作为去重依据，同一条消息只生效一次。event_id 仅用于标识同一个持续事件，不参与消息去重
2. 乱序消息：time 不递增的旧消息不得覆盖新状态，不触发状态转移，不中断验证计数
3. 迟到消息：早于事件当前状态的旧消息，无法回滚已 RECOVERED 事件，仅作为历史记录补充

## 7 测试证据

### 测试案例：完整事件链路

1. 触发异常：zone-w 重度污染，crowdLevel=2，事件 OPEN
2. 用户干预：点击干预，选择喷雾降尘，状态 HANDLING
3. 第 1 组后续数据：pm25 下降，轻度污染，存入验证列表，状态保持 HANDLING
4. 第 2 组后续数据：pm25 正常，crowdLevel 空闲，满足恢复条件，状态变为 RECOVERED
5. 事件归档，保存全部记录。

### 额外证据：迟到消息测试

事件已经 RECOVERED，发送一条更早时间的旧异常报文，事件状态不会回退，仅追加历史记录。

## 8 和其他模块联动

- D3 复用 D1 MQTT 数据流、D2 优先级计算
- 总视图 index.html、3D 页面 three-min.html 同步展示同一事件状态（3D 中 OPEN 白色边框、HANDLING 橙色闪烁、RECOVERED 恢复原色，点击建筑查看事件详情）
- 干预动作经 MQTT 广播：总视图点击干预后向 `airguard/{zone}/action` 发布指令，所有订阅端同步 OPEN → HANDLING，多端状态一致
