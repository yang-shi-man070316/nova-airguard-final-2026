# E1 地图/3D 数字空间增强 · 操作手册（three3d/three-min.html）

> 适用版本：2026-10-04 更新后的 three-min.html（外框/光圈/发光/聚焦增强版）
> 页面文件：`three3d/three-min.html`（单文件，three.js / mqtt.js 走 CDN，纯前端无后端）

## 一、前置条件

| 项 | 要求 |
|---|---|
| MQTT Broker | mosquitto 运行中，TCP 1883 与 WebSocket 8083 均在监听 |
| 数据源 | sensor_sim.py（任意模式）或 MQTTX 手工发报文 |
| 打开方式 | 浏览器直接打开 `three3d/three-min.html`，页面自动连接 `ws://127.0.0.1:8083/mqtt` |
| 干净起点（建议） | 先执行 `python sensor_sim.py clear` 清除保留消息，再刷新页面 |

连接状态看右上角：绿点=已连接，红点=断开（自动重连中）。

## 二、数据契约

页面订阅 `airguard/+/env`（环境报文）与 `airguard/+/action`（干预指令），报文字段与全端一致：

```json
{"zoneId":"zone-w","pm25":40,"co2":700,"crowdLevel":2,"time":"2026-10-04 16:30:00"}
```

- `zoneId` 取值 `zone-n`（宿舍区）/ `zone-s`（教学区）/ `zone-w`（食堂区），兼容小写 zoneid，缺失时退回主题中段
- `time` 必须逐条递增：重复报文被去重拦截，时间倒流的迟到报文只补历史、不改变任何状态
- 干预指令：`airguard/{zone}/action`，载荷 `{"zoneId":"zone-w","action":"开启净化"}`（也可由总视图 index.html 的 D3 干预按钮自动广播）

## 三、视觉元素总览（每个元素的含义与状态表现）

| 视觉元素 | 位置 | 状态表现 |
|---|---|---|
| 建筑外框（线框） | 建筑外圈 | 正常=绿色；异常（轻度/重度污染、通风不足）=红色；无数据/离线=灰色；D3 处理中=黄色闪烁；事件恢复=黄色平滑渐变回绿 |
| 人流密度光圈 | 建筑地面一圈 | 等级 0→3：尺寸逐级放大 25%/级（最大 1.75 倍）、闪烁频率逐级加快、颜色 灰→绿→橙→红；无数据/离线淡出隐藏 |
| D2 发光光晕 | 优先建筑头顶 | 红色加色光晕呼吸脉冲（叠加红色半透明高亮壳），仅当前优先关注区域显示 |
| D3 状态壳 | 建筑外一层半透明盒 | OPEN=白色静止；HANDLING=橙色闪烁（与外框黄闪同时出现）；无事件/已恢复=隐藏 |
| D5 提醒壳 | 最外层 | 规则与 ML 结论不一致=黄色闪烁；一致=隐藏 |
| 地面热力光斑 | 建筑下方地面 | 径向渐变光斑，透明度=状态严重度+人流，颜色=状态色 |
| 顶部文字标签 | 建筑上空 | 区域名 + 状态（+ML不一致标注）+ 处置建议；离线灰显「已离线」 |
| 悬浮信息面板 | 画布左上角 | 点击建筑后弹出，见第四节第 6 条 |

## 四、各项功能操作说明

### 1. 基本视角操作（全程可用）

- 按住鼠标左键拖拽：水平/俯仰旋转视角
- 滚轮：拉近拉远（距离 12~70）
- 点击空白处：无动作（与拖拽区分，位移 >5px 视为拖拽不触发点击）

### 2. 建筑外框动态颜色（环境状态直读）

| 环境状态 | 外框颜色 | 触发方式 |
|---|---|---|
| 正常（pm25≤75 且 co2<1500） | 绿色 | 正常报文 |
| 轻度污染（pm25>75） | 红色 | 异常报文 |
| 重度污染（pm25>150） | 红色 | 异常报文 |
| 通风不足风险（co2≥1500） | 红色 | 异常报文 |
| 暂无数据 / 节点离线 | 灰色 | 初始状态 / 超过 2 分钟无报文 |

外框颜色由页面按统一判级规则从 pm25/co2 实时计算，**不信任报文里的 status 字段**；每条新报文到达当刻变色，无页面刷新。

### 3. D3 干预—验证—恢复 全链路联动

| 阶段 | 3D 表现 | 触发 |
|---|---|---|
| OPEN 待处理 | 外框按环境色（异常即红）+ 白色半透明状态壳 | 异常报文到达 |
| HANDLING 处理中 | **外框黄色快速闪烁** + 橙色状态壳闪烁 | 人工点击干预（见下） |
| RECOVERED 已恢复 | **外框从黄色平滑渐变回绿色**（1.2 秒缓动），状态壳隐藏 | 处理后连续 2 条正常报文 |

干预方式（二选一）：

1. 打开 `web/index.html`，在 D3 面板对该区域点「干预」→ 指令经 MQTT 广播，3D 页同步进入 HANDLING；
2. MQTTX 向 `airguard/{zone}/action` 发 `{"zoneId":"{zone}","action":"开启净化"}`。

注意：HANDLING 期间若又收到更严重的异常报文，状态机回退 OPEN（干预无效）；已恢复事件不会被迟到/重复报文回滚。

### 4. 人流密度动态光圈

由报文 `crowdLevel` 驱动，逐级对照：

| crowdLevel | 尺寸（倍率） | 闪烁频率（rad/s） | 光圈颜色 |
|---|---|---|---|
| 0 稀疏 | 1.00 | 1.2（几乎静止） | 灰 |
| 1 正常 | 1.25 | 3.4 | 绿 |
| 2 拥挤 | 1.50 | 5.6 | 橙 |
| 3 严重拥挤 | 1.75 | 7.8（快速闪动） | 红 |

尺寸变化为平滑过渡（约半秒缓动），不突变；等级变化随每条报文实时生效。

### 5. D2 优先关注区域发光

- 判定：综合风险分 = 环境基础分 + 人流附加分 + 持续异常加成，总分最高的异常区域胜出（同分依次比连续异常次数、状态严重度）
- 表现：胜出建筑头顶出现**红色发光光晕**（加色混合呼吸脉冲）+ 红色半透明高亮壳
- 触发时机：**首条异常报文到达当刻立即生效**（收到有效报文即视为在线，无需等待巡检）
- 全部区域正常 → 无发光；优先区域离线（>2 分钟无报文）→ 发光自动取消

### 6. 点击建筑：相机聚焦 + 实时信息面板

1. 点击任意建筑（非拖拽）→ 相机约 0.9 秒平滑移动并拉近对准该建筑（smoothstep 缓动）
2. 左上角弹出悬浮信息面板，内容：
   - 实时 PM2.5 / CO₂ / 人流密度（中文+L 等级）/ 状态
   - D5 判定：固定规则结论 + ML 结论 + 动态阈值（pm25/co2）+ 是否 ⚠不一致
   - D3 事件：OPEN/HANDLING（含处置与连续正常计数）/ RECOVERED/无事件
3. 面板打开期间收到新报文，**面板内容实时刷新**（页面不刷新）
4. 「回到全景视角」按钮：镜头平滑飞回全景；面板 8 秒无操作自动关闭

### 7. 左侧数据面板（与 3D 联动）

- 区域实时数据：PM2.5 / CO₂ / 人流 / 上报时间 / 空间对象 / 处置建议
- D2 优先关注：当前胜出区域 + 判定理由（可解释打分）
- D3 事件状态：三区 OPEN/HANDLING/已恢复/无事件 逐行显示
- D4 链路状态：Broker 连接 + 各区域在线/离线 + lastSeen；「手动重连」按钮强制断开重建
- D5 规则与ML：规则结论 + ML 结论 + 一致性，与 3D 黄壳同步

### 8. 实时更新与离线机制

- 所有动画/颜色/光圈由状态驱动，MQTT 每收到一条报文即时重绘，全程无页面刷新（F12 Network 中无任何页面请求，仅 websocket 数据流）
- 区域超过 2 分钟无新报文 → 判为离线：模型灰显、外框变灰、光圈淡出、发光取消、标签显示「已离线」、D3 事件冻结；恢复上报立即还原

## 五、完整验收流程（按序执行，约 10 分钟）

**准备**：broker 运行 → `python sensor_sim.py clear` → 打开 three-min.html。

**场景 A 外框 + D2 发光**（MQTTX 发三条，time 逐条用当前时间递增）：

| 主题 | JSON |
|---|---|
| `airguard/zone-n/env` | `{"zoneId":"zone-n","pm25":30,"co2":500,"crowdLevel":0,"time":"当前时间"}` |
| `airguard/zone-s/env` | `{"zoneId":"zone-s","pm25":40,"co2":600,"crowdLevel":1,"time":"当前时间"}` |
| `airguard/zone-w/env` | `{"zoneId":"zone-w","pm25":160,"co2":900,"crowdLevel":1,"time":"当前时间"}` |

预期：zone-n/zone-s 绿框；zone-w 红框 + 头顶红色发光光晕脉冲 + 红高亮壳（**首条报文当刻出现**），左侧 D2 面板显示「优先关注：食堂区」。

**场景 B 人流光圈**：向 `airguard/zone-w/env` 连发 crowdLevel=0/1/2/3 四条（其余字段不变）→ 光圈逐级放大、闪动加快、颜色灰→绿→橙→红。

**场景 C D3 黄闪→渐变恢复**：

1. zone-w 发 `{"pm25":160,"co2":900,"crowdLevel":1}` → 红框+白状态壳（OPEN）
2. 干预：index.html D3 面板点「干预」，或 MQTTX 向 `airguard/zone-w/action` 发 `{"zoneId":"zone-w","action":"开启净化"}` → **外框黄色快速闪烁**（HANDLING）
3. zone-w 连发两条正常报文（pm25 35→30，crowdLevel=1）→ 第 2 条到达时 RECOVERED，**外框黄色平滑渐变回绿色**（约 1.2 秒），左侧 D3 显示「已恢复」

**场景 D 点击聚焦 + 面板实时**：点击教学区钟楼 → 镜头平滑飞近；面板显示 PM2.5/CO₂/人流/D5/D3；面板开着时再发一条报文 → 面板数值实时跳动；点「回到全景视角」复位。

**场景 E 实时性验证**：全程观察无页面刷新；F12 Network 确认无页面请求。

**清理**：`python sensor_sim.py clear` → 刷新页面回到「灰框+无光圈」初始态。

## 六、常见问题

| 现象 | 原因与处理 |
|---|---|
| 看不到 D2 发光光晕 | 优先区域必须同时满足：有异常报文 + 在线。首条异常报文已立即生效（新版修复）；仍看不到请确认该区域确实是当前唯一/最高分异常区，或 F12 看是否有 JS 报错 |
| 外框一直灰色 | 无数据（等待报文）或节点离线（>2 分钟无报文）。恢复发报即变色 |
| 黄色外框不停闪烁 | 该区域 D3 事件处于 HANDLING 处理中，属正常提醒；完成后会渐变回环境色 |
| 光圈突然消失 | 该区域离线或无数据；或 crowdLevel 字段缺失（非法报文被丢弃） |
| 点击建筑没反应 | 拖拽超过 5px 视为旋转不触发点击；确认点的是建筑本体（可用框选区域建筑） |
| 面板数据不动 | 面板内容只在收到新报文时刷新；停发报文则数值定格，属正常 |
